# Known limitations (cloud, data and operations)

Owner: Akanksha (Member 04). Deliverable from `docs/team/member-04-akanksha.md`, section I.1 ("Known limitations list").

**This is a snapshot taken on 18 Nov 2026 against `main` at `44dc0d8`; every row was re-checked against that commit.** Earlier snapshots
(12 Nov at `4e936df`, 16 Nov at `e62aaa4`, and partial re-checks on 13 Nov) are superseded. It lists what the cloud, data and operations
workstream does **not** do or has **not** verified, so nobody reads a green test run as more than it is. Each row cites
where the evidence lives. Pull request states ("open", "merged") are as of the snapshot and go out of date: check
GitHub before relying on them. Remove a row when the limitation is closed, with a link to what closed it (see section 6).

Legend for "Needs": **Account** = a Supabase or GitHub administrator action; **Decision** = a reviewer or partner
answer in `docs/team/open-questions-and-assumptions.md`; **Work** = code or documents that can be written now.

## 5. What would change this list

The largest single unlock is an administrator creating the three Supabase projects and the GitHub environments (L1 to L4,
L15 to L18). The work that needs no account is: re-land the restore drill, runbook and alert catalog on `main` (L5, L17,
L18, pull request #61); agree that the retention migration takes its number at promotion (L10, OQ-64, pull request #58); agree the enrolment
contract (L9); then the retention, alert and export migration (L10) once OQ-12, OQ-47
and OQ-48 are answered.
